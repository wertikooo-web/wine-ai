# Как работать с WineMD-персонажем на Rive

Пошаговая инструкция для человека. Технические детали и контракты — в `.claude/skills/winemd-rive/references/`; здесь только "что делать и в каком порядке".

## Что это и зачем

У проекта уже есть работающий 2D-аватар на CSS/DOM (`public/visual/VisualStoryController.mjs`) — статичная картинка с анимацией рта по громкости звука. Rive-версия — это **вторая, более качественная** реализация того же самого: настоящий скелетный риг вместо CSS-трансформаций, тот же самый поток событий от сервера. Обе версии не конфликтуют — Rive не заменяет существующую систему, а подключается параллельно к тем же событиям.

## Как вызвать Skill

В новой сессии Claude Code напиши:

> Используй skill winemd-rive, начни Phase 1 персонажа WineMD (Idle, Blink, Speaking, Present Wine, формы рта).

Или для диагностики проблемы:

> Используй skill winemd-rive, разберись, почему [конкретная анимация/жест] не работает.

Skill сам сначала перечитает актуальное состояние `tools/WineMD-Character-SDK/` и `src/visual/` — не полагается на устаревшие предположения.

## Какие исходники нужны

Уже есть в `tools/WineMD-Character-SDK/00_reference/`:
- `master_character_source.png` — исходная плоская картинка персонажа (реальная, ~2.2 МБ).
- `master_character_cutout_approx.png` — приблизительный вырез (реальный, ~2.1 МБ).
- `01_art_pipeline/layer_map.png` — карта слоёв-подсказка (реальная, ~1.25 МБ).

**Чего пока нет и что нужно получить/сделать:**
- Настоящий **многослойный PSD** — его нельзя автоматически собрать из плоской картинки. Нужен художник (человек или Photoshop-инструмент), работающий по спецификации `references/psd-layer-contract.md` (точное дерево слоёв) и `references/art-pipeline.md` (требования к мастер-арту).
- Настоящий **`.riv`-файл** — в репозитории его нет вообще. Собирается вручную в Rive Editor.

## Что Claude может сделать сам

- Прочитать и сверить всю документацию SDK с реальным кодом (`src/visual/*`, `realtimeServer.js`).
- Написать/поправить JS-адаптер, который переводит реальные события `visual.*` в формат `SommelierEvent` (файл `05_runtime/src/SommelierController.ts` нужно портировать в обычный `.js`/`.mjs` — TypeScript-сборки в проекте нет).
- Написать спецификации анимаций, чек-листы, отчёты о несостыковках.
- Запускать валидаторы (`npm run avatar:validate`) и сообщать точный результат.
- Обновлять `AGENTS.md`/скрипты/шаблоны Skill'а.

## Что требует Rive Editor или художника (Claude сделать не может)

- Рисование скрытой геометрии (плечи под рукавами, шея под подбородком и т.д.) — см. `references/psd-layer-contract.md`.
- Сборка PSD в реальный многослойный файл.
- Импорт слоёв в Rive, построение костей (`references/rive-rig-contract.md`), создание State Machine с нужными inputs (`references/state-machine-contract.md`).
- Рисование самих анимаций (Idle, Blink, Speaking и т.д.) внутри Rive.
- Экспорт итогового `.riv`.

## Как проверить MVP (Phase 1)

1. Запусти `npm run avatar:validate` — проверяет манифест, пример события и найденные PNG/riv/psd файлы (без внешних сервисов, ничего не меняет).
2. Открой готовый `.riv` в реальном браузере через Rive web runtime — убедись, что State Machine грузится без ошибок в консоли.
3. Пройди чек-лист `references/testing-checklist.md`, раздел "Phase 1 verification" — включая живой тест через реальный диалог (`realtimeServer.js`), а не только вручную собранное тестовое событие.
4. Отдельно проверь прерывание диалога (interruption) — это заявлено в контракте, но никогда не было протестировано вживую.

## Куда положить готовый `.riv`

Точный путь ещё не выбран (не был нужен до появления файла) — при первой реальной интеграции зафиксируй его в `references/runtime-integration.md` и держись той же логики, что уже использует `public/visual/` для остальных ассетов (например `public/visual/winemd-sommelier.riv`, если не найдётся причина иначе).

## Как передать работу следующему агенту

Всегда заканчивай сессию отчётом по шаблону `templates/implementation-report.template.md`:
- что создано/изменено,
- точный вывод трёх валидаторов,
- что осталось непроверенным или ждёт человека/Rive Editor,
- одна конкретная следующая задача.

Следующий агент должен получить возможность продолжить, просто прочитав этот отчёт и `SKILL.md` — не переспрашивая заново то, что уже выяснено.
