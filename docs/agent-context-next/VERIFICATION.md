# VERIFICATION.md

Проверка выбирается по изменённой поверхности. Полный набор не запускается после каждой мелкой правки.

## Во время работы

1. Запусти ближайший unit-тест или syntax-check для изменённого модуля.
2. Проверь новый или исправленный сценарий воспроизводимым тестом.
3. Просмотри diff и убери случайные изменения.

## Перед завершением кодовой задачи

- `npm run check:missing-imports` для изменений импортов, startup и структуры;
- релевантные unit-тесты;
- `node --test tests/startupNoAdminAuth.test.js` для server/auth/startup;
- `npm run test:smoke` для API, frontend, websocket и release-sensitive правок;
- реальный HTTP/browser check после изменений routes или frontend scripts.

## Перед merge или deploy

Требуются все deployment gates из `INVARIANTS.md` и зелёный workflow `startup-smoke`.

## Документация и контекст

Для Markdown-правок проверь:

- правило имеет одного владельца;
- ссылки ведут на существующие файлы;
- главный файл содержит маршрутизацию, а процедура лежит в отдельном документе;
- утверждения о поведении совпадают с кодом и тестами;
- в примерах нет реальных ключей, токенов и паролей.

Честно укажи проверки, которые нельзя было запустить.
